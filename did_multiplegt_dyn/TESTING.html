Testing did_multiplegt_dyn

Check that a new Stata, R or Python version of did_multiplegt_dyn still gives the same results as Stata, the reference. Everything runs on your own computer.

The suite runs 121 specifications and 14 input checks in Stata, R and Python, then compares every result with Stata's. Known differences: DIFFERENCES.html. History of fixes: CHANGELOG.md.

Type the commands in a terminal: PowerShell or Git Bash on Windows, Terminal on Mac or Linux. Lines starting with # are comments. The R and Stata commands in step 1 go in the R console (or RStudio) and in Stata. If python is not found on Windows, use py instead.

Step 1. Install the software (once)

  1. Git: git-scm.com.
  2. Stata with gtools (tested with Stata 18 MP). In Stata: 
    ssc install gtools, replace
  3. R (tested with R 4.5). In the R console: 
    install.packages(c("haven", "pkgload", "data.table", "MASS", "fixest", "dplyr", "ggplot2",
                   "openxlsx", "car", "lmtest", "sandwich", "cowplot", "rnames", "Rcpp"))
install.packages("polars", repos = "https://rpolars.r-universe.dev")
    To test R source code (see example A2) you also need a compiler: Rtools on Windows, or xcode-select --install on Mac.
  4. Python 3 (tested with 3.12). In the terminal: 
    python -m pip install numpy pandas scipy statsmodels matplotlib seaborn pyarrow "polars>=1.3,<2"
    Keep polars below 2: the package does not work with polars 2 yet.

Step 2. Get the test suite (once)

git clone https://github.com/anzonyquispe/DCDH_TODO.git
cd DCDH_TODO/did_multiplegt_dyn

All the following commands are run from this did_multiplegt_dyn folder. Next time, update the suite first with git pull.

Step 3. Make the reference run (once)

This runs everything with the versions already installed on your computer, so later runs have something to compare with. It takes about 1½ hours (Stata ~60 min, R ~20 min, Python ~15 min).

# quick check first (about 2 minutes): one spec in each language
python run_jobs.py --stata-ado installed --r-pkg installed --py-pkg installed --only "A01"

# the full run
python run_jobs.py --stata-ado installed --r-pkg installed --py-pkg installed

installed means "the version installed in Stata / R / Python". It is never assumed: you always say which version each language uses.

To keep this result for later, copy the results folder, e.g. to results_reference.

Step 4. Test a new version from a zip file

Create a folder called new_versions inside did_multiplegt_dyn (Git ignores it) and copy the zip file into it. Then unzip it there and point the suite at the unzipped folder. The command python -m zipfile -e <zip> <folder> unzips on every system:

mkdir new_versions

Use --skip to reuse the last results of the languages you are not testing: only the new version is run, and it is compared with Stata's results from step 3.

A. New R version

First look at what the zip contains after unzipping:

  • a folder with libs inside: a ready-built package (e.g. a Windows .zip from CRAN or a colleague) → example A1;
  • a folder with DESCRIPTION, R, man and src inside: source code (e.g. GitHub's "Download ZIP") → example A2.

A1. Ready-built zip, e.g. DIDmultiplegtDYN_2.5.0.zip, copied into new_versions:

python -m zipfile -e new_versions/DIDmultiplegtDYN_2.5.0.zip new_versions/R_2.5.0
python run_jobs.py --r-pkg new_versions/R_2.5.0 --skip stata,python

(new_versions/R_2.5.0 now contains the folder DIDmultiplegtDYN; the suite loads it from there without installing it.)

A2. Source zip, e.g. did_multiplegt_dyn-main.zip downloaded from GitHub (it contains the R and Stata code):

python -m zipfile -e new_versions/did_multiplegt_dyn-main.zip new_versions
python run_jobs.py --r-pkg new_versions/did_multiplegt_dyn-main/R --skip stata,python

Point --r-pkg at the folder that contains DESCRIPTION. The package is compiled on the fly, which needs Rtools on Windows. A source .tar.gz file can also be given directly, without unzipping (it needs Rtools too): --r-pkg new_versions/DIDmultiplegtDYN_2.5.0.tar.gz.

B. New Python version

E.g. py_did_multiplegt_dyn-main.zip downloaded from GitHub (or a zip of a branch):

python -m zipfile -e new_versions/py_did_multiplegt_dyn-main.zip new_versions
python run_jobs.py --py-pkg new_versions/py_did_multiplegt_dyn-main/src --skip stata,r

Point --py-pkg at the folder that contains the did_multiplegt_dyn package folder (here src). Nothing is installed: your installed version stays as it is.

C. New Stata version

E.g. did_multiplegt_dyn_stata.zip containing did_multiplegt_dyn.ado (and its .sthlp):

python -m zipfile -e new_versions/did_multiplegt_dyn_stata.zip new_versions/stata_new
python run_jobs.py --stata-ado new_versions/stata_new --skip r,python

Point --stata-ado at the folder that contains did_multiplegt_dyn.ado (if the zip has a subfolder, add it to the path). Your installed ado is not touched. Stata is the reference, so this re-runs Stata (~60 min, 6 specs at a time) and compares R's and Python's last results with the new Stata.

Several new versions at once

python run_jobs.py --stata-ado new_versions/stata_new --r-pkg new_versions/R_2.5.0 --py-pkg new_versions/py_did_multiplegt_dyn-main/src

Useful options: --only "A01 D18" runs only some specs; --merge-only re-does the comparison without running anything; --stata-workers 3 runs fewer Stata jobs at a time (less memory).

Step 5. Read the result

The last line in the terminal says RESULT: ALL CHECKS PASSED or the number of failed checks. Then open:

results/report.txtOne verdict per spec and language, then all problems grouped by kind.
results/details.csvEvery single check: spec, element, Stata's value, the other language's value, difference.
results/jobs/<lang>/<spec>/console.logThe output of one job, if it crashed.

Verdicts

PASSEqual to Stata within 1e-7 + 1e-6·|x|; counts exactly equal.
WARNEverything compared passes; the language also returns something Stata does not store (e.g. N_*_w without weights). Not a failure.
PASS*Everything compared passes; an option's output is NOT_SUPPORTED in this language.
FAIL / MISSING / ERRORA value differs, is not returned, or the run crashed. Investigate these.
NOT_SUPPORTEDThe language lacks the option (specs/not_supported.csv). Not a failure.
STATA_NOT_SUPPORTED / STATA_ERRORThe Stata ado under test cannot run the spec, so there is no reference.

Did the new version fix or break something?

Compare the new results/report.txt with the one saved in step 3 (results_reference/report.txt), and check DIFFERENCES.html for differences already known. When you fix something, add an entry to CHANGELOG.md.

Comparison rules

  • e(b) is not compared: its numbers are compared one by one as Effect_#, Placebo_#, Av_tot_effect and their se_*.
  • With weight(), Stata's e(N_*) scalars hold the weighted count; they are compared with R/Python N_*_w. Stata's table is compared with their unweighted N.
  • The Av_tot_eff row of e(V): its diagonal is compared with the SE² of the R/Python ATE table; its zero covariances are Stata placeholders and are not compared.

If something goes wrong

Stata not foundOn Windows the suite looks in C:\Program Files\Stata*. Otherwise set its path, e.g. on Mac: export STATA_BIN=/Applications/Stata/StataMP.app/Contents/MacOS/stata-mp; in PowerShell: $env:STATA_BIN = "D:\Stata18\StataMP-64.exe".
Rscript not foundAdd R's bin folder to your PATH, or set RSCRIPT the same way as STATA_BIN.
"Could not find tools necessary to compile a package"You gave R source code (example A2) without Rtools. Install Rtools, or use a ready-built zip (A1).
Python: pl.count errorpolars 2 is installed: python -m pip install "polars>=1.3,<2".
A job says DID NOT FINISHRead its console.log. "memory allocation failed" means the computer ran out of memory: close other programs or use --stata-workers 3. The largest spec (D10) needs about 6 GB.

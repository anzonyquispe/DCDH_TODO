Testing did_multiplegt_dyn

Check that a new Stata, R or Python version still gives Stata's results. Stata is the reference.

1. Install once

  • Stata with gtools (ssc install gtools).
  • R with haven, polars (install.packages("polars", repos = "https://rpolars.r-universe.dev")) and pkgload.
  • Python with numpy pandas "polars<2".
  • On Windows, run the commands below from Git Bash, inside the did_multiplegt_dyn/ folder.

2. Say which versions to test

Nothing is assumed. Each option takes installed or a path:

--stata-adoinstalled, or the folder or file containing did_multiplegt_dyn.ado
--r-pkginstalled, a source folder (with DESCRIPTION), or a .tar.gz
--py-pkginstalled, or the folder containing the did_multiplegt_dyn package (e.g. …/src)

To test a branch that is not released yet, check it out in the package's repository and point the option at its source folder. For example, for the Python fixes on branch fix_bypath_weights:

git -C ../../py_did_multiplegt_dyn checkout fix_bypath_weights
python run_jobs.py --py-pkg ../../py_did_multiplegt_dyn/src --skip stata,r

3. Run

Every spec runs as its own job. Stata runs 6 at a time, then R and Python run one spec at a time. A full run takes about 1 hour.

python run_jobs.py --stata-ado installed --r-pkg installed --py-pkg installed

Useful variants:

# only the package you changed (Stata's last results are reused)
python run_jobs.py --r-pkg ../../did_multiplegt_dyn/R --skip stata,python

# a few specs
python run_jobs.py --stata-ado installed --r-pkg installed --py-pkg installed --only "A01 D10"

# re-merge existing jobs and compare again, without running anything
python run_jobs.py --merge-only

4. Read the result

Open results/report.txt. It gives one verdict per spec and language, then every problem grouped by kind. Every single check is in results/details.csv.

PASSEqual to Stata within 1e-7 + 1e-6·|x|. Counts must be exactly equal.
WARNEverything compared passes; the language also returns something Stata does not store (e.g. N_*_w without weights). Not a failure.
PASS*Everything compared passes; some output of an option is NOT_SUPPORTED in this language.
FAIL / MISSING / ERRORA value differs, is not returned, or the run crashed. Investigate these.
NOT_SUPPORTEDThe language lacks that option (listed in specs/not_supported.csv). This is not a failure.
STATA_NOT_SUPPORTEDThe Stata ado under test can't run the spec, so there is no reference.

Everything is OK when the last line says RESULT: ALL CHECKS PASSED (exit code 0). To see whether a release fixed or broke something, compare against the report from a run on the previous version.

Three comparison rules to know:

  • e(b) is not compared: its numbers are compared one by one as Effect_#, Placebo_#, Av_tot_effect and their se_*.
  • With weight(), Stata's e(N_*) scalars hold the weighted count; they are compared with R/Python N_*_w. Stata's table is compared with their unweighted N.
  • The Av_tot_eff row of e(V): its diagonal is compared with the SE² of the R/Python ATE table; its zero covariances are Stata placeholders and are not compared.

Differences already known: DIFFERENCES.html. Fixes and changes to the suite: CHANGELOG.md.

If a job crashes, look at results/jobs/<lang>/<spec>/console.log.

5. Where things are

specs/specs.csvThe 121 specifications, written in Stata syntax. Add a row to add a test.
specs/option_map.csvStata option → R / Python argument. Add a row for every new option.
specs/element_map.csvWhere each Stata e() result is found in the R and Python objects.
specs/validation.csvInputs that must be accepted or rejected.
CHANGELOG.mdOne entry per issue found: symptom, cause, fix, evidence. Add an entry for every fix.
R_bootstrap/Bootstrap tests for R. They run separately; see their README.

Status (22 Nov 2026)

Stata ado dated January 17th, 2026 (reference), R 2.4.0, Python from branch fix_bypath_weights. Of the 121 specs, 97 have a Stata reference. Python passes 78 of them (PASS, WARN or PASS*) and R passes 1. Both pass 8 of the 10 input checks that Stata can run. Details: DIFFERENCES.html.
